# Phase 3: EDA, Visualization & Dashboard (W6–W7)

**Baseline:** `Dung` at commit `7655897` (Phase 2). Scope: **#12, #13, #14**. Phase 1–2 metric contract is authoritative: `docs/data_dictionary.md`.

## 1. Single source of truth

The **only** Phase 3 input is `data/processed/ecommerce_customer_clean.csv` generated by the Phase 2 pipeline from Kaggle's original `ecommerce_customer_data_custom_ratios.csv`.

- **No legacy fallback**: `ecommerce_customer_cleaned.csv` previously filled missing `Returns` with 0; do NOT use it for Phase 3.
- `Returns` keeps 47,596 NULLs; `Returns_was_missing` must match those NULLs; a mismatch raises an error.
- Dashboard and chart script use `src/eda_metrics.py` so aggregations share definitions.
- Source dataset is **synthetic** and currency has **not** been established. Never label these amounts *real revenue* or USD.
- Dashboard hides `Customer Name` in the public-facing sample table; source CSV remains untouched.

## 2. What was fixed

| ID | Prior problem | Phase 3 change |
|---|---|---|
| #12 | Figure 01 hardcoded "Electronics và Clothing" despite Books and Clothing ranking higher | Figure title is computed dynamically from category sums; no USD/revenue assertion |
| #13 | Figures hardcoded unit USD, false uniform/stable trends, 2020-12 hardcoded as monthly peak, final incomplete month appearing as a collapse; figure generation deleted all other files in figures/ | Chart content recalculated from validated CSV; distribution avoids unsupported distribution claims; peak chosen from complete months; incomplete boundary months flagged; only 01–05 overwritten, preserve 06–09 |
| #14 | KPI churn weighted by transactions, `Returns` missing imputed 0, 20% benchmark invented, stale PNGs, dashboard silent fallback to legacy CSV | Churn = customer-level average, Returns = observed-only rate + missing count, no benchmark, charts generated from the same validated CSV, no legacy fallback |

**Segmentation nuance:** Heatmap counts each customer once **per product-payment cell**. One customer may belong to multiple cells, so heatmap cells aren't independent and cannot demonstrate causality.

**Monetary split:** `sum(Total Purchase Amount)` differs from `sum(Product Price × Quantity)` for 249,952 of 250,000 rows. Both are displayed as distinct metrics with unverified currency; no arithmetic reconciliation is forced.

**Temporal nuance:** 2023-09 ends on 15 September, so that month's total is incomplete. The line graph preserves it with an orange marker and excludes incomplete months when highlighting the largest full month. Monthly totals are not normalized by number of days or transactions.

## 5. Known limitations and deliberate non-goals

- Dataset license, currency and `Total Purchase Amount` generation semantics remain unresolved in Phase 1.
- Return rate for missing observations cannot be inferred; descriptive rate is conditional on being observed.
- Churn snapshot timing not defined; the heatmap is descriptive, **not** a prediction or a causal result.
- The test suite does not assert statistical validity of the hypotheses, regression, or figures 06–09. Those belong to Phase 4.
- Generated chart PNGs are reviewable artifacts; the live dashboard doesn't trust them and renders directly from the clean CSV.
